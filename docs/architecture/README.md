## Main flow: requesting and attending a visit

```mermaid
sequenceDiagram
    actor V as Visitor
    participant C as client
    participant S as server
    participant VY as Vonage Verify
    participant VV as Vonage Video
    participant VM as Vonage Messages
    V->>C: Requests a visit with date and phone number
    C->>S: Sends the request
    S->>VY: Starts verification
    VY-->>V: OTP code by SMS
    V->>C: Enters the code
    C->>S: Sends the code
    S->>VY: Checks the code
    VY-->>S: Phone verified
    S->>VV: Creates the visit session
    S->>VM: Schedules confirmation and reminder
    VM-->>V: Confirmation SMS
    Note over V,VV: On the day of the visit
    C->>S: Requests access to the room
    S-->>C: Session token
    C->>VV: Joins the visit
```

## Design principles

- **Vonage credentials live only in `server/`.** The client never receives the API secret or the private key; for video it only receives the session token generated by the server  
- **All communication with users goes through the server**, so every verification, message and visit is recorded and traceable  
- **Vonage webhooks** notify the server of message status, so the agency dashboard reflects what actually happened
